# GitHub issue lifecycle

Use the `sdlc-github-issue` skill.

Without explicit `vamos trabalhar <issue-number>` authorization, monitor only and do not write to GitHub. After authorization, use the issue number in the branch, local documents, issue-plan comment, progress comments, evidence summary, and pull request.

Run the authorized issue through completion. Comments must be concise and sanitized. AWS inspection is allowed only when necessary, only as read-only, and only in this authorized GitHub mode.
